# IAC AI Runtime — Ownership Boundary

## Owner

IAC owns this repository, its company-domain records, its deployments, and its IAC integration configuration. It is intended to remain transferable with IAC in a sale.

## Allowed

- IAC goals, projects, tasks, decisions, knowledge, approvals, agents, and audit events
- Chief of Staff functions operating within IAC scope
- Revenue Agent research and internal preparation
- IAC-owned integrations after their independent production gates are approved
- IAC Railway deployment configuration

## Prohibited

- PERSONAL records, prompts, backups, identifiers, credentials, or configuration
- Family, health, wealth, or private-life context
- Direct access to a PERSONAL database or personal source repository
- Autonomous customer contact, production mutation, spending, or money movement

## Enforcement

The worker and interface open only an `IAC`-bound database. Profile binding is permanent and rejects PERSONAL records even for Sean-level actors. PERSONAL scope constants remain in generic validation code solely to test and enforce denial, export isolation, and migration safety; they grant no PERSONAL runtime capability.

## Bridge

Any future direction from personal Sean OS enters through a versioned, allowlisted command contract. The IAC runtime must remain operable, reviewable, and transferable without the personal repository or database.
